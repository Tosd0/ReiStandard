# Blob 存储规范（blob-store）

> 版本：v1.0
>
> 状态：当前生效（Active）
>
> 版本日期：2026-08-19
>
> 对齐实现：`@rei-standard/blob-store`（当前版本以其 `package.json` / npm 为准）。

纯前端应用二进制存储的规范化描述。面向想自己实现（而不是安装 `@rei-standard/blob-store`）的读者；包的行为以本规范为准。

## 1. 模型

- 二进制以 Blob 形式存进 IndexedDB 的一张表；业务数据里不出现二进制，只出现**令牌**。
- 令牌 = `<prefix><id>`，prefix 默认 `blobref:`。令牌是普通 string，可 JSON 序列化、可结构化克隆。自定义 prefix 应以 §2 id 字符集之外的字符收尾（如 `:`）——`pic` 这类收尾仍在字符集内的前缀会把普通字符串（如 `picture.png`）误判成令牌。
- id 对消费者**不透明**：任何实现不得解析他人生成的 id 语义，只能整串比对。

## 2. id 格式（参考实现）

`b_<毫秒时间戳 base36>_<进程内序号 base36>_<随机 6 位 base36>`

时间戳字段供 GC 的新鲜豁免反解。其他格式的存量 id 合法——读写不受影响，仅 GC 按「老」处理。「参考实现」指具体拼法可换；但「新生成的 id 能反解出创建时间」是 §5 新鲜豁免的硬要求，换格式也必须保留这一能力（或以其他机制实现同等豁免），不属于可参考可不参考的部分。

id 只能由 `[A-Za-z0-9_]` 组成，不能含 `-` 等其他字符。GC 从文本里提取令牌时，是按这个字符集划边界的（见 §5 mark 步骤）：边界之外的字符一律当成令牌已经结束。带 `-` 的 id（比如直接拿 UUID 当 id）会在第一个越界字符处被截断，截出来的半截对不上真实 id——这类 id 结构上不可能出现在「在用」集合里，「无引用」对它们不构成孤儿证据。因此 sweep 必须把超出字符集的 id 一律保留（见 §5 安全要求）：读写不受影响，代价是它们永远不被回收；想让这类存量 id 参与回收，先迁移成本节格式。

## 3. 存储适配器契约

实现方通过四个方法对接任意后端：

| 方法 | 语义 |
|---|---|
| `get(id) → Promise<Blob \| null>` | 不存在返回 null |
| `put(id, blob) → Promise<void>` | 失败必须抛出（调用方要知道没存上） |
| `delete(id) → Promise<void>` | 幂等 |
| `keys() → Promise<string[]>` | 全量 id，GC 扫描用 |

## 4. 错误语义

| 操作 | 失败时 |
|---|---|
| get / resolve | 返回 null / 空串，不抛 |
| delete | 静默 |
| put | 上抛 |
| 迁移（data URL → 令牌） | 回退返回原始输入 |

原则：存储层错误不打断业务；抛错只发生在明确的编程错误上。

## 5. 孤儿 GC

mark-and-sweep：

1. **mark**——宿主枚举全部可能含令牌的持久化面（数据库各表、localStorage 等），对每段字符串按 prefix 提取令牌（prefix 之后取最长 `[A-Za-z0-9_]` 段），汇总在用 id 集合。
2. **sweep**——`keys()` 中不在集合里的 id 删除。

安全要求（必须全部实现）：

- 任一引用来源枚举失败 → 整轮放弃，不删任何东西。
- 新鲜豁免：id 可反解创建时间且距今不足阈值（参考值 72h）的不删——挡住「已 put、引用尚未持久化」的竞态窗口。实现所生成的 id 必须内嵌可反解的创建时间，否则须以其他机制实现同等的豁免——本条不是可选项：id 用纯随机（比如 hex UUID 去掉 `-`，完全落在合法字符集内）时这道阀会静默失效，上述竞态窗口完全裸奔，而实现自身看起来处处合规。
- 反解不出时间的 id 按「老」处理。「反解不出时间」包括两种情况：一是 id 本身不是 §2 的参考格式（比如宿主存量的其他命名），从中取不出时间戳字段；二是取出来的时间戳明显不合理——超过当前时间 24 小时以上，说明这不是本方案生成的 id（多半是外来 id 恰好撞上了参考格式的前缀），也按反解失败处理。两种情况都不给新鲜豁免，直接按「老」判：否则一个凑巧匹配格式、时间戳读出来是未来的外来 id 会被新鲜豁免永久保护，永远不参与 GC，造成空间泄漏。
- 单个删除失败不中断整轮，按保留计。
- 超出 §2 令牌字符集的 id 一律保留，不参与删除判定：这类 id 不可能被 mark 到，「不在集合里」不构成孤儿证据——宁可永不回收，不冒误删。
- 边界歧义豁免：存储 id 与「在用」集合中的某个 id 互为前缀时不删。这是令牌被拼进复合键（提取出的 id 比真实 id 长）或引用面文本在令牌中间被切开（只提出半截 id）时留下的痕迹，「无引用」同样不构成孤儿证据。实现须把这道豁免的命中数在结果里单独暴露：一段恰好以令牌前缀开头的杂散文本（如把令牌格式当例子写进被扫的面）会提出一个超短「在用」id，让每个存储 id 都命中此豁免、GC 整轮空转，而删除数为 0 与「没垃圾」同形——单独计数是宿主唯一的察觉手段。
- 入参形态校验：引用来源传错（单个字符串、吐非字符串、不可迭代）应当抛出而不是静默跑完——空的标记集会把全库当孤儿。

**宿主义务（任何一条做不到都会删活图，是接入方必须自己保证正确的全部内容）：**

- **引用面清单要全**，且每个面吐出的字符串必须是令牌逐字可见的明文（压缩、加密或编码过的面先还原再吐——这种情况枚举不报错、安全阀也不触发，但令牌不可见等于该面没扫）。
- **一张 blob 表（一个适配器 `keys()` 的覆盖范围）只能对应一个令牌前缀。** mark 只认本 store 的前缀、sweep 却扫整张表：多前缀共表时任何一个 store 的 GC 都会把其他前缀引用的活图当孤儿删掉，且不触发任何安全阀。要按资产种类分类，分表而不是分前缀。
- **GC 一轮进行期间，引用面上不得发生令某个令牌暂时从所有面上消失的写入**（先删后写的重存、跨面搬家）：mark 不是一致性快照，恰好撞上扫描就会漏标误删（老图没有新鲜豁免可救）。多实例 / 多 tab 场景应保证 GC 独跑（如 `navigator.locks`），或只在单实例静默期触发。
- **吐出的文本要保持令牌边界完整**：令牌之后不得紧跟 §2 字符集内的字符（拿令牌拼复合键请用字符集外的分隔符），分块吐大文本不得把令牌从中间切开（按记录/行切）。安全要求里的边界歧义豁免只是兜底——切在前缀边界上时连前缀关系的痕迹都不剩，兜底也救不了。

## 6. 备份互操作

- 导出前：深度遍历备份对象树，令牌原地替换为 data URL；解析不到的令牌置空串。**备份文件里永远没有令牌**——备份格式与是否采用本方案解耦，跨设备、跨实现可恢复。
- 遍历只需覆盖普通对象与数组；二进制视图（TypedArray / DataView）应整块跳过——元素是数字、结构上不含令牌，逐下标枚举只会把大数组（波形、纹理这类几十 MB 的面）的导出拖垮。
- 导入侧：按普通 data URL 处理即可；可选地惰性转回令牌（读到 data: 时顺手 put 并替换）。

## 7. 渲染

令牌经 `URL.createObjectURL` 转 objectURL 喂给 `<img>` / CSS。实现方必须管理生命周期：消费点卸载或值变化时 revoke，防止内存泄漏。
